# 初回の構築の作成物 × 失敗の地点の検証表（D-026 S1）

> 2026-11-26（Codex 監査23 の構造的な対応）。すべて **モック（Apps Script API の偽の実装）・GAS エミュレーション** での検証。Google 実環境では未検証（docs/live-verification.md）。
> 判定は偽の API・エミュレータが持つ作成物の件数（実体）で行い、エラーの応答だけでは判定していない。
> 不変条件: どの組み合わせでも、作成物は最終的にちょうど 1 つ。結果が分からない間は、確認の明示・関連付けがあるまで作らない。

## 共通の状態

| 状態 | 記録 | 再実行での扱い |
|---|---|---|
| 未作成 | 目印なし・ID なし | （Core の構成物は検索で見つかれば使う）目印を保存してから作成を要求する |
| 作成予定・結果不明 | 目印あり（要求の前に保存） | 照合（デプロイ: 一覧の説明／Core: appProperties の検索）で 1 つ見つかれば使う。見つからなければ作らずに止め、確認・関連付けを案内する |
| ID を永続化 | ID あり（読み直して確かめる） | 目印を外す（ID の保存を確かめた後だけ） |
| 完了 | ID あり・目印なし | 記録の ID を照会する。照会で見つからない（一時的な 404 を含む）ことだけでは作り直さない |
| 要確認 | 重複・照会できない | 停止。所有者が確認・整理・関連付けをする（自動では削除しない） |

## 構築の完了前の検証（確認の工程）

| 項目 | 方法 | 結果の扱い |
|---|---|---|
| 未解決の作成中・要確認の状態がない | Setup の記録 | 問題があれば完了しない |
| プロジェクトの存在と名前（環境 ID 付き） | Apps Script API の照会 | 同上 |
| Shiftly のデプロイが 1 つずつで、記録の ID・Web アプリの URL と一致 | デプロイの一覧・照会 | 同上（自動では削除しない） |
| Admin の接続先が Staff の URL で、Admin・Setup との接続が完了 | Admin のコードの取得・Core の ping | 同上 |
| Core の保管先（フォルダ・DB・環境情報ファイル）が 1 つずつで保存済み ID と一致、目印なし | Core の system.storageCheck（Drive の検索） | 同上。点検できない環境は問題として扱う |
| DB の構造 | Core の system.integrityCheck | 同上 |
| Apps Script のプロジェクトの重複 | **自動では確かめられない**（Setup の権限 drive.file では一覧できない） | 完了の記録に「未確認」として残し、完了画面で確認を案内する（検証済みとして扱わない） |
