## 重要な指摘

### 1. 高 — ロールバック後、旧管理画面から不整合な状態で営業を再開できる

- **根拠・再現条件（コード読解）**　v1.2 からの更新で DB が v2 になった後に完了処理が失敗すると、Setup は Core と Admin を旧版に戻してメンテナンスを継続します。その状態で Google 所有者が旧管理画面の「メンテナンスを解除」を押すと、`b093a80` の `system.ts` 152–159 行は DB の版を照合せず解除します。現行 Core の解除ガードはロールバック後の実行コードに含まれません。 [installer.ts](../../src/setup/installer.ts:493) · [installer.ts](../../src/setup/installer.ts:524) · [system.ts](../../src/backend/handlers/system.ts:173)
- **影響・推奨修正**　v1.3 の休憩申告やシフト外確認を扱えない Core で打刻・給与処理が再開します。互換性を判定できる Core を稼働させ、DB を対応する版へ復元してから旧版へ切り替える復旧順序に変更してください。

### 2. 高 — シフト外の 1 区間を確認すると、同じ分の別区間まで確定対象から外れる

- **根拠・再現条件（モック Core で再現）**　公開シフト 09:00–17:00、時給 1,200 円、打刻は出勤 09:00、休憩 17:00:10–17:00:20、退勤 17:00:40。管理画面で最初の 10 秒だけ「実労働なし」として選ぶと、画面が送る範囲は 17:00–17:01 です。その入力をモック Core に渡すと、直後の 20 秒も未確認一覧から消え、基本賃金 **9,600 円**でシフト外確認のブロックが出ません。期待値は残る 20 秒を確認するまで確定不可で、実労働と確認した場合は **9,607 円**です。 [Requests.tsx](../../src/frontend/admin/pages/Requests.tsx:373) · [requests.ts](../../src/backend/handlers/requests.ts:730) · [worktime.ts](../../src/shared/worktime.ts:148)
- **影響・推奨修正**　同じ分に複数の候補がある勤務で、未確認の実労働が給与から抜けます。画面から候補の正確な開始・終了を送り、Core で対象勤務の候補区間と照合して保存してください。

### 3. 高 — 一部承認の再審査で、撤回した「実労働なし」が残る

- **根拠・再現条件（モック Core で再現）**　シフト 09:00–17:00、打刻 09:00–17:10、休憩なし、時給 1,200 円。17:00–17:05 を一部承認し、残りを「実労働なし」とします。同じ申請を再審査し、承認区間を維持して残りを「未確認」に変更します。期待値は仮 **9,700 円**で確定不可、残りも実労働なら **9,800 円**です。実際は旧確認が残り、仮 **9,700 円**で未確認のブロックが出ません。 [requests.ts](../../src/backend/handlers/requests.ts:615) · [requests.ts](../../src/backend/handlers/requests.ts:646) · [worktime.ts](../../src/shared/worktime.ts:108)
- **影響・推奨修正**　再審査で保留した実労働が支払対象から抜けます。残区間の確認を元申請と構造的にひも付け、再審査時に旧確認を失効させてから新判断を反映してください。旧判断は履歴に残してください。

### 4. 高 — 時刻未設定で申告した予定休憩に、後日の編集で新たな控除が入る

- **根拠・再現条件（モック Core で再現）**　シフト・打刻とも 09:00–17:00、時給 1,200 円。予定休憩は 30 分で開始時刻なしとし、「予定どおり」で退勤します。その後、同じシフトを休憩 12:00–13:00 に変更して再公開します。仮計算は **480 分・9,600 円**から **420 分・8,400 円**に変わりました。期待値は、実際の区間を確認するまでは時刻未設定の扱いを維持し、30 分の取得が確認された時点で **450 分・9,000 円**とすることです。 [requests.ts](../../src/backend/handlers/requests.ts:106) · [attendance.ts](../../src/shared/attendance.ts:317)
- **影響・推奨修正**　同じ申告のまま取得していない休憩まで控除されます。申告時点の「時刻未設定」を明示的に保存し、現在のシフトから区間を補わず、実際の区間の確認を求めてください。

### 5. 高 — Staff の PIN ログインを閉じても、遅延応答で本人画面が開く

- **根拠・再現条件（コード読解、iPad 未確認）**　Staff が PIN を確定し、応答待ちにキャンセルするかタブを非表示にした場合、PIN 付きの送信処理は成功応答を受けるとそのまま本人セッションを採用します。キャンセル後は氏名選択画面を維持するのが期待値ですが、コード上は本人画面へ遷移します。 [StaffApp.tsx](../../src/frontend/staff/StaffApp.tsx:274) · [StaffApp.tsx](../../src/frontend/staff/StaffApp.tsx:362) · [StaffApp.tsx](../../src/frontend/staff/StaffApp.tsx:383)
- **影響・推奨修正**　共用 iPad に本人確認済み画面が残り、付与済みの権限に応じて勤怠や給与を閲覧できる状態になります。管理者ログインと同様に、キャンセル・非表示・アンマウントで試行を無効化し、遅延応答で発行されたセッションを失効させてください。

### 6. 中 — 退職済み Staff の未申請勤務がシフト外確認一覧に出ない

- **根拠・再現条件（コード読解）**　時給 1,200 円の Staff が 09:00–17:00 のシフトに対して 17:10 まで勤務し、申請・確認の前に退職処理を行います。対象期間の給与計算には引き続き含まれ、仮の基本賃金は **9,600 円**、確定はブロックされます。一方、シフト外確認一覧は在籍中の Staff に限定され、該当の 10 分が表示されません。期待値は一覧から確認でき、実労働と確認した場合に基本賃金 **9,800 円**となることです。 [services.ts](../../src/backend/services.ts:157) · [services.ts](../../src/backend/services.ts:277) · [requests.ts](../../src/backend/handlers/requests.ts:689)
- **影響・推奨修正**　退職前の未申請勤務があると、通常の管理画面から最終給与の確定条件を満たせません。閲覧対象を現在の在籍状態で絞らず、対象期間に勤務や未確認区間がある Staff を含めてください。
