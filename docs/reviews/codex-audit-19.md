### マージ前に対応する指摘

1. **高 — 復元後、控除額が異なっても給与訂正の停止を解除できる。** 解除時の再計算が比較するのは `grossPay` だけです。控除はチェック欄の値で確認済みと扱うため、別画面で控除が変わっても画面の比較結果は「差なし」のままです。**再現入力**は月給24万円、控除4万円の状態でバックアップを取得し、控除なしに変更して差引24万円で確定した後、そのバックアップを復元する手順です。**期待値**は、確定時の控除に戻すまで解除を拒否し、訂正を停止することです。**実際の値**は、総支給額が双方24万円、比較結果が差あり0人で解除に成功し、控除を変更する意図のない訂正でも差引20万円になりました。影響範囲は、復元された控除が確定時と異なる期間の給与訂正です。解除時に同じロック内で差引支給額と控除明細も比較し、計算に確定を妨げる問題がある場合は解除を拒否してください。画面にも差がある項目を表示してください。[比較処理](/home/user/shiftly/src/backend/handlers/payroll.ts:56)・[解除処理](/home/user/shiftly/src/backend/handlers/payroll.ts:275)・[訂正処理](/home/user/shiftly/src/backend/handlers/payroll.ts:311)
2. **中 — 初回 Setup の「再実行」で、応答を失った作成要求が二重作成になる。** 作成 API が成功した後に応答だけを失うと、最初のエラーは通常の再実行を案内します。画面の「再実行」は、前回の作成結果を確認するための目印を消してから進むため、重複確認の案内を通りません。**再現条件**は、モックで `core.create` の成功応答だけを失わせ、その直後に画面と同じ `retry` → 実行を行うことです。Staff プロジェクトは1件から2件に増え、再実行はエラーなしで進みました。Staff・Admin 共通の作成処理に影響し、Google 所有者の Drive に Setup の管理外となるプロジェクトが残ります。作成結果が不明なら最初の失敗から照合を案内し、既存プロジェクトを確認・処理したことを明示する操作まで目印を保持してください。既存テストは通常実行を挟み、模擬プロジェクトを手動で削除してから再試行するため、画面の直後の再実行をカバーしていません。[エラー処理](/home/user/shiftly/src/setup/installer.ts:263)・[再試行処理](/home/user/shiftly/src/setup/installer.ts:538)・[画面](/home/user/shiftly/src/frontend/setup/SetupApp.tsx:137)・[既存テスト](/home/user/shiftly/tests/integration/installer.test.ts:264)
