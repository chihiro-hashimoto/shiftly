# セキュリティ設計

## 1. 脅威と前提

- 公開された GAS Web アプリの URL は、知っていれば誰でも呼べる前提（Core は匿名アクセス）
- 共用 iPad は複数のスタッフが触る。ブラウザの端末トークンは複製可能な認証情報であり、物理的な iPad の完全な識別は保証できない
- 店長の Google アカウントには Shiftly 以外のファイルがある（保護対象）
- Google Drive の所有者（店長）による直接編集は技術的に防止できない（監査ログ・原本と修正の分離で検知性を高める）

## 2. 認証

| 主体 | 方式 | 実装 |
|---|---|---|
| 店長 | Google 認証（Admin=アクセス自分のみ）→ Admin が HMAC-SHA256 で署名し Core へ転送（60 秒の時刻窓・ノンスでリプレイ防止） | src/gas/admin.ts, src/backend/auth.ts |
| Setup | 同上（role=setup）。許可操作は更新関連のみ（SETUP_ALLOWED_OPS） | auth.ts |
| 店舗端末 | 店長が発行した 10 文字・15 分・使い捨ての登録コード → 256bit 端末トークン（DB には SHA-256 のみ）。失効可能 | auth.ts |
| スタッフ | 端末トークン＋氏名選択＋個別 6 桁 PIN。セッションは発行端末に紐づき、絶対 30 分・無操作（既定 60 秒＋猶予）で失効 | auth.ts |
| 機密操作 | 別の管理用パスコード（10 文字以上、英数字混在）による追加認証（5 分間） | auth.ts / api.ts |

- ブラウザ入力で owner/system を名乗ることはできない（`handleRequest` の trusted 引数はサーバー側でのみ指定）
- OAuth アクセストークンはサーバー（GAS）内でのみ使用し、ブラウザ・URL・ログ・DB に出さない

## 3. PIN・パスコードの保護

- 保存: `hash = PBKDF2-HMAC-SHA256(password = HMAC(pepper, PIN), salt[16B], 1000 回, 32B)`。平文は保存しない
- pepper（32 バイト乱数）は Core の Script Properties にのみ保存し、DB・バックアップに含めない → DB が漏えいしてもオフライン総当たりができない
- オンライン試行制限: 個人 5 回失敗で 15 分ロック（設定変更可）、端末単位で 15 分 20 回、登録コードは全体で 15 分 30 回
- 定数時間比較、PIN の形式制限（同一数字の繰り返し・連番を禁止）
- PIN・パスコードの設定/リセットは店長専用（スタッフ管理権限でも他人の PIN は変更不可）

## 4. 認可（docs/permission-matrix.md）

- 全 op にサーバー側の認可。UI の非表示に依存しない
- 権限は毎リクエスト DB から再読込 → 変更は既存セッションの次の操作から反映
- 自己操作の禁止: 自分の勤怠修正・給与条件・雇用条件・有給・給与確定/訂正・退職処理
- 個人給与の推定防止: `payroll_view_all` がない人件費分析では個人別・1 名のみの日・時間帯別の金額を返さない
- IDOR: 本人用 op は ID 引数を受け取らず、セッションの本人のみを対象。他人の明細はサーバーで本人性を確認

## 5. 入力検証・出力

- サーバー側で型・範囲・形式を検証（src/backend/validate.ts）。日付・時刻・金額・ID のパターンを限定
- CSV: `= + - @ TAB CR` で始まる文字列セルに `'` を付与（数式インジェクション対策）、UTF-8 BOM
- Sheets 書き込み: `valueInputOption=RAW`（数式評価させない）
- XLSX: inlineStr（文字列として格納）
- XSS: React のエスケープのみ（`dangerouslySetInnerHTML` 不使用。lint ルール・コードレビューで確認）。PDF 用 HTML は全値をエスケープ
- エラー応答に内部情報（スタック・個人情報）を含めない

## 6. 端末へのデータ保存

| データ | 保存先 |
|---|---|
| 端末トークン | localStorage（`shiftly.device.v1`）のみ |
| 勤怠・給与・シフト・個人情報・PIN・OAuth トークン | 保存しない（React state のみ） |

- ログアウト・打刻完了・無操作・タブ非表示・bfcache 復元でセッション終了と state 破棄
- HtmlService のレスポンスヘッダーは制御できないため、HTTP キャッシュ・ページ復元・PDF 表示の残存は完全には制御できない（meta の no-store、共用 iPad では明細を HTML 表示のみ・ダウンロード不可で軽減）。**iPad 実機での確認は未実施**
- キャッシュクリアで失われるのは端末トークンのみ（再登録で復旧。クラウドの業務データは失われない）

## 7. Google Drive の保護

- Core は drive.file（Shiftly が作成したファイルのみ）。フル drive・spreadsheets スコープは要求しない
- 削除はアプリ管理フォルダ配下のバックアップのみ（親フォルダを確認しゴミ箱へ。完全削除しない）
- スタッフへの Drive 共有はしない（共有 API を使用しない）

## 8. 監査ログ

- 権限変更・PIN 設定・端末登録/失効・勤怠修正・給与確定/訂正・明細の他者閲覧・出力・バックアップ/復元・設定変更・認証失敗/ロックを記録
- 個人情報・秘密情報（PIN・トークン）は記録しない（テストで確認）

## 9. 残存リスク（受容・要対応）

| リスク | 内容 | 対応 |
|---|---|---|
| 乱数品質 | `Utilities.getUuid()` の乱数源の暗号学的品質は公式に明記なし | 複数 UUID を連結し SHA-256 で整形。要確認事項として記録 |
| 端末トークンの複製 | 同じトークンを別端末に複製できる | 失効→再登録の手順。最終利用日時で異常検知 |
| Setup ホスト型 | 配布者のコードが店長の権限で動く（配布者を信頼する必要） | 自己ホスト型を推奨。配布物の SHA-256 検証は配布経路内の破損・改ざん検知 |
| Drive 所有者の直接編集 | DB を直接編集できる | 原本・修正の分離、監査ログ、整合性チェック。完全防止はできない |
| Google アカウント喪失 | 同一アカウント内のバックアップでは不十分 | docs/operations-guide.md の別管理アカウントへの保護されたバックアップ手順（店長の承認後に実施） |
| GAS 実行時の制約 | HTTP ヘッダー（CSP 等）を設定できない | React のエスケープ、外部スクリプトは Google Fonts の CSS のみ |

## 10. 依存パッケージの脆弱性（npm audit, 2026-11-24）

- 本番に含まれる依存（`npm audit --omit=dev`）: **0 件**
- 開発用のみ: moderate 8 件（eslint / typescript-eslint が依存する minimatch の ReDoS: GHSA-g3hv-75wg-m249）。lint 実行時のみ使用され、配布物（GAS・HTML）には含まれない。修正は破壊的な版上げ（`npm audit fix --force`）が必要なため保留し、上流の修正版リリース後に更新する
