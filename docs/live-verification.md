# 実環境検証の手順と記録（検証用 Google アカウント）

> 2026-11-24 ユーザー承認済み（検証用アカウントでの実環境検証）。
> 2026-11-26: 初回の構築で Web アプリのデプロイの作成の応答が失われた場合、Setup は再開時にデプロイの一覧（説明）で照合して既存のデプロイを使う（Codex 監査17 #3）。実際の Apps Script API の一覧の応答（説明が含まれること）は未検証のため、L1 の構築で確認する。
> 2026-11-26: 初回の構築でプロジェクトの作成の結果が分からない失敗（通信の例外・タイムアウト・5xx）が起きた場合、Setup は最初の失敗から一覧での確認を案内し、確認のチェックがあるまで作り直さない（D-025）。実環境では、L13 で中断・再実行の際に案内とチェックが表示されることを確認。Web アプリのデプロイの作成も同じ（一覧で説明を照合し、見つからなければ確認のチェックまで作らない）。実環境では、デプロイの一覧の応答に説明が含まれること・作成から一覧への反映の時間を確認する（未検証）。
> 2026-11-26（Codex 監査22 の対応）: Setup の記録ファイルは、Drive の `Files.generateIds` で予約した ID を指定して作成する（`Files.create` の `id`）。Core の初期化のフォルダ・DB は、作成の前に目印を保存し、結果が分からない間は検索で見つからなくても作らずに止める（`shiftlyConfirmStorageNotCreated` で目印を外す）。実環境では、L1・L3・L13 で、①予約した ID での記録ファイルの作成が成功すること ②作成から Drive の検索（appProperties）に反映されるまでの時間 を確認する（**未検証**。①が使えない場合は Setup の保存が失敗するため、初回の構築で必ず分かる）する。
> 2026-11-26（Codex 監査23 の構造的な対応。D-026）: 実環境では次を確認する（**未検証**）。①復元の後、復元前に開いていた Shiftly-Admin・店舗 iPad の画面で保存すると「画面を読み込み直してください」が表示され、読み込み直すと保存できる（L12 に続けて確認）②Script Properties の復元世代が、復元のたびに大きくなる ③初回の構築の完了画面に「完了前の確認」が表示され、Core の保管先の点検（system.storageCheck）が実環境の Drive の検索で ok になる ④Setup の権限（drive.file）で Apps Script のプロジェクトを一覧できないこと（できる場合は、重複の確認を自動化できる）⑤Drive の appProperties の検索への反映の時間
> 2026-11-26: まだ公開しておらず利用者はいない（D-024）。L11（アップデート・ロールバック）は、v1.3 の公開後に**次の版を出す前に必ず実施**する（途中の失敗・手動ロールバック・再開を含む。docs/update-rollback.md）。
> **本番の管理者アカウントは使わない。実在スタッフの情報は登録しない（架空の氏名・PIN を使う）。**
> 開発用コンテナからは Google にログインできないため、操作は検証担当者がブラウザで行い、結果をこの表に記入する（スクリーンショット・エラー全文を添えると原因調査が速い）。

## 0. 準備物

- 検証用 Google アカウント（個人の Gmail で可。2 段階認証を推奨）
- PC（Chrome 推奨）、可能なら iPad（Safari）
- 配布物: リポジトリで `npm ci && npm run build && npm run build:gas` → `dist/gas/setup/`（または GitHub Actions の Artifacts「shiftly-gas-bundle」）

## 1. 手順

| # | 作業 | 参照 |
|---|---|---|
| 1 | 検証用アカウントで https://script.google.com/home/usersettings を開き「Google Apps Script API」をオン | google-api-setup.md §1 |
| 2 | Google Cloud で標準プロジェクトを作成し、Apps Script API・Google Drive API を有効化、OAuth 同意画面（テスト、テストユーザー＝検証用アカウント）を設定。**課金の設定を求められたら中止** | google-api-setup.md §2 |
| 3 | 検証用アカウントで Setup プロジェクトを作成し `dist/gas/setup/` の 4 ファイル（appsscript.json / Code / Release / setup.html）を配置、Cloud プロジェクト番号を紐づけ、ウェブアプリとしてデプロイ（実行: 自分、アクセス: 自分のみ） | installer-guide.md §1-A |
| 4 | Setup の URL を開いて権限を承認し、店舗名（例「検証店」）を入力してセットアップを開始 | installer-guide.md §2 |
| 5 | 指示に従い Shiftly-Staff のエディタで `shiftlyAuthorize` を実行 → 承認 → 「確認して続行」 | 同上 |
| 6 | Shiftly-Admin のエディタで `shiftlyAuthorize` を実行 → 承認 → 「確認して続行」 → 完了画面 | 同上 |
| 7 | 管理画面: 店舗設定（最低賃金等）→ 給与規定の確認 → 架空スタッフ 2 名登録・PIN 設定・時給/交通費 → 端末登録コード発行 | installer-guide.md §3 |
| 8 | 別ブラウザ（シークレットウィンドウ）または iPad で店舗 iPad 用 URL（Shiftly-Staff）を開き、登録コード入力 → 打刻（出勤・退勤。退勤時に休憩の確認） | §4 |
| 9 | 下の検証項目を順に確認 | — |

## 3. 終了後
