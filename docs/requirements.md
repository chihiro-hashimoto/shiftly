# 要件（統合マスタープロンプト v1.2 ＋ 追加仕様変更 v1.3 の要点）

> 正式な指示は統合マスタープロンプト v1.2（2026-11-24）と追加仕様変更指示 v1.3（2026-11-25）、およびリリース範囲適正化指示（B案、2026-11-27。docs/decisions.md D-027）。v1.3 で変更した部分は v1.3 を優先し、それ以外の v1.2 の確定済み要件・F01〜F37・安全ルールは維持する。ただし B案で次期以降に延期した機能（下の「v1.3 のリリース範囲」）は、v1.3 の完成の条件に含めない。本書は再入力なしで作業を継続するための要約。

## 製品
- Shiftly（シフトリー）: 店舗勤怠・給与・シフト・人件費管理 Web アプリ。日本語、Asia/Tokyo、JPY
- 対象: ダーツバー・飲食店 1 店舗、スタッフ 10 名以下、曜日で営業時間が異なり深夜 0 時をまたぐ勤務あり、現状は紙のタイムカード
- 端末: 店舗共用 iPad 1 台でスタッフ操作と管理者操作を完結（v1.3。縦横対応、オフライン打刻は対象外）。管理者の PC・スマホからの利用（Shiftly-Admin、Google 認証）も維持するが、別端末を通常運用の必須条件としない
- 雇用: 時給・月給混在、個人別・曜日・時間帯別時給、休憩は予定休憩（標準）・打刻・手動を併用、交通費は個人別、控除は手動入力、締め日・支払日は設定可、通知はアプリ内のみ
- 認証: Google 所有者は Google（全権限・構築・保守作業（データの復元・更新は手動）・管理者パスワードの設定）、店舗 iPad の管理者は管理者パスワード（v1.3）、スタッフは氏名選択＋個別 PIN（v1.3: PIN は任意）、スタッフ単位の権限、共用 iPad に Google ログインを残さない

## 必須条件（無断変更禁止）
月額無料／Supabase・Cloudflare Pages・有料サーバー/DB/API 不使用／GAS バックエンド／Sheets を DB／Drive をストレージ／管理者本人の Google アカウント内／初回に Google 連携／GAS・DB・フォルダの自動構築／業務データを端末へ永続保存しない（端末認証情報のみ可）／キャッシュクリアでクラウドデータが消えない／管理者 Drive の無関係なファイル保護／スタッフへ Drive 直接共有しない／サーバー側で認証・権限検証／GitHub は Private 維持／実データ・認証情報を GitHub・AI 環境に保存しない／本番と開発・テストの分離

## v1.3 のリリース範囲（B案。2026-11-27。D-027）

方針: **正常時は自動・異常時は手動**。日常業務の機能と初回の自動構築・安全な再開・自動／手動のバックアップは v1.3 の対象。障害時のデータの復元・アプリの更新・ロールバックは、アプリ内の自動処理ではなく Google 所有者の保守作業（手動）として行う。

分類: **初回** = 初回リリース対象／**一部手動** = 一部を Google 所有者の手動の保守作業で行う／**延期** = 次期以降に延期（v1.3 では実行できない。サーバー側で拒否）。
Google 実環境・iPad 実機での検証は、すべての機能で未実施（**実環境検証待ち**。docs/live-verification.md）。延期した機能を実装済みとして数えない。機能 ID は削除・流用しない。

## 導入方法の A案（2026-11-27。D-029）

- 開発者が共通の Shiftly Setup を公開し、利用者自身の Google アカウントの中に Shiftly の環境を自動構築する（保守の B案と両立）
- 利用者の操作の目標: 共通 Setup の URL を開く → Google アカウントの選択・承認 → Apps Script API がオフならオン → 「再確認」 → 店舗名の入力 → 構築の内容の確認 → 自動構築（途中で Staff・Admin の権限の承認をブラウザで行う） → 完了 → 管理者パスワードの設定 → 店舗 iPad の登録 → 利用開始
- 利用者に求めない: Google Cloud のプロジェクトの作成・API の有効化・OAuth の同意画面・GAS のプロジェクトの手動作成・コードの貼り付け・マニフェストの編集・手動のデプロイ・プロジェクト番号の入力・Drive のフォルダとスプレッドシートの作成・通常時のスクリプトエディタの操作
- 現時点で残る利用者の操作（実環境の結果で見直す）: Apps Script API のオン（Google の仕様）、Google の承認画面での許可（Setup・Staff・Admin）、構築の完了の前のプロジェクト一覧の確認（重複の確認。自動化は未検証のため保留。D-029）
- 自己ホスト型（利用者が Setup を自分で配置する従来の方法）は、開発者・検証用の別の方法として残す

## 対象外
スタッフからのシフト希望提出、自動シフト生成、税・社会保険料率からの自動計算、年末調整、メール/LINE 等の外部通知、オフライン打刻

## 承認が必要な事項
本番デプロイ、main へのマージ、実在スタッフの登録、正式な給与支払いへの利用、有料サービス、外部公開、データ破壊・不可逆変更、給与規定など管理者しか知らない情報、Codex 監査 6 回目以降

## 未確定事項（設定画面・導入手順で後から登録。架空の確定値を使わない）
iPad 機種/OS、Drive 空き容量、曜日別営業時間、営業日の切替時刻、労働時間制度、週 40/44 時間、法定休日、週の起算日、36 協定、月給制の規定、固定残業代、個別時給、曜日・時間帯別時給、交通費規定、各種手当、締め日・支払日、電子明細の交付条件、過去の有給残日数、紙タイムカードの移行範囲

> 注: 週 44 時間特例は「常時 10 人未満」が要件。「スタッフ 10 名以下」は 10 名の場合に要件を満たさないため、自動適用しない（管理者が確認してフラグを設定）。
