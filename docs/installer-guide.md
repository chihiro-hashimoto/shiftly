# 導入手順（Shiftly Setup）

> **本番導入はユーザー（管理者）の承認後に実施**します。まず検証用の Google アカウントで試すことを推奨します。

## 0. 必要なもの

- 管理者の Google アカウント（2 段階認証を推奨）
- PC（Chrome / Edge / Safari）
- 店舗の iPad（Safari）
- 事前準備: `docs/google-api-setup.md`（Apps Script API をオン、Setup 用 Cloud プロジェクト）

## 0.5 初めて Google Apps Script（GAS）を使う方へ（ブラウザだけで行う導入の流れ）

GAS は、Google が用意する、ブラウザの中でプログラムを動かす仕組みです。Shiftly は、Google 所有者の Google アカウントの中に 3 つの GAS のプロジェクト（Shiftly Setup・Shiftly-Staff・Shiftly-Admin）と、Google ドライブの `Shiftly` フォルダ（データベースのスプレッドシートなど）を作って動きます。費用はかかりません。

**始める前に**
- 使う Google アカウント（Google 所有者）を決める。**検証（docs/live-verification.md）では検証用のアカウント、本番では店舗の Google 所有者のアカウント**を使い、検証の環境を本番に流用しない
- Chrome でそのアカウントだけにログインする（複数のアカウントに同時にログインしていると、承認の画面で取り違えやすい。シークレットウィンドウか、Chrome のプロフィールを分けると安全）
- 本番の実データ（スタッフ・給与条件）は、検証（live-verification.md の公開前の必須項目）を終えてから登録する
- 画面で**課金（クレジットカード）の登録を求められたら中止**して、開発者に連絡する

**手順 A: 配布物（Setup のファイル）を入手する**
1. GitHub の Release「Shiftly v1.3.0」から **shiftly-gas-bundle.zip** をダウンロードし、Release に記載の SHA-256 と一致することを確認してから展開する（非公開のリポジトリのため、GitHub へのログインと閲覧の権限が必要。開発者から受け取ってもよい）
2. 展開したフォルダの `setup` の中に、`appsscript.json`・`Code.js`・`Release.js`・`setup.html` の 4 つがあることを確認する（ほかに `core`・`admin` があるが、手で使わない。Setup が自動で配置する）

**手順 B: Apps Script API をオンにする（1 回だけ）**
1. https://script.google.com/home/usersettings を開く
2. 「Google Apps Script API」のスイッチをオンにする

**手順 C: Google Cloud のプロジェクトを作る（Setup が Apps Script API を使うため。1 回だけ）**
1. https://console.cloud.google.com/ を開き、利用規約に同意する（求められた場合）
2. 画面上部のプロジェクトの選択 →「新しいプロジェクト」→ 名前「shiftly-setup」→ 作成
3. 左のメニュー「API とサービス」→「ライブラリ」で「Google Apps Script API」を検索して「有効にする」。同じく「Google Drive API」も「有効にする」
4. 「API とサービス」→「OAuth 同意画面」（表示によっては「Google Auth Platform」）で、アプリ名「Shiftly Setup」、サポートメール（検証用アカウント）、ユーザーの種類「外部」を設定し、**テストユーザーに検証用アカウントを追加**する
5. 「ダッシュボード」（またはプロジェクトの情報）に表示される**プロジェクト番号**（数字だけのもの）を控える
   - 画面の名前・配置は Google の変更で変わることがあります（詳しくは docs/google-api-setup.md）

**手順 D: Shiftly Setup のプロジェクトを作る**
1. https://script.google.com/ →「新しいプロジェクト」。左上の「無題のプロジェクト」をクリックして名前を「Shiftly Setup」にする
2. 左の歯車「プロジェクトの設定」→「『appsscript.json』マニフェスト ファイルをエディタで表示する」にチェック
3. 左の「<>」（エディタ）に戻り、ファイルを 4 つ用意する（中身は手順 A のファイルを開いて**すべて選択してコピーし、貼り付けて置き換える**）
   - `appsscript.json`: すでにあるので、中身を置き換える
   - `コード.gs`（または `Code.gs`）: すでにあるので、名前を `Code` にし、中身を `Code.js` で置き換える
   - 「ファイル」の「＋」→「スクリプト」で `Release` を作り、中身を `Release.js` で置き換える
   - 「ファイル」の「＋」→「HTML」で `setup` を作り、中身を `setup.html` で置き換える
4. 上の保存のアイコン（フロッピー）で保存する。赤いエラーが出た場合は、貼り付けの漏れがないか確認する
5. 「プロジェクトの設定」→「Google Cloud Platform（GCP）プロジェクト」→「プロジェクトを変更」→ 手順 C-5 のプロジェクト番号を入力 →「プロジェクトを設定」
6. 右上の「デプロイ」→「新しいデプロイ」→ 左の歯車で「ウェブアプリ」を選び、**次のユーザーとして実行: 自分**、**アクセスできるユーザー: 自分のみ** →「デプロイ」→ 表示された「ウェブアプリ」の URL を控える

**手順 E: Setup を実行して Shiftly を構築する**
1. 手順 D-6 の URL を開く。承認を求められたら、検証用アカウントを選ぶ
   - 「このアプリは Google で確認されていません」と表示された場合: 自分で作ったプロジェクト（手順 D）であることを確認したうえで「詳細」→「Shiftly Setup（安全ではないページ）に移動」→ 権限の一覧を確認して「許可」
2. 店舗名を入力して「セットアップを開始」。以後は画面の案内に従う（installer-guide.md §2）
   - 「スクリプトエディタを開く」と案内されたら、開いたエディタの上部の関数の選択で **shiftlyAuthorize** を選び「実行」→ 承認（上と同じ警告が出たら同じ手順）→ Setup の画面に戻り「確認して続行」。これを Shiftly-Staff と Shiftly-Admin で 1 回ずつ行う
   - 最後に「自動では確かめられない項目があります」と表示されたら、https://script.google.com/home のプロジェクト一覧で「Shiftly-Staff (…)」「Shiftly-Admin (…)」が 1 つずつであることを確認し、チェックを付けて「確認したので再実行」（L18）
3. 完了画面の**管理者用 URL**（PC 用）と**店舗 iPad 用 URL**（QR コード）を控える
4. 途中で止まった・エラーが出た場合は、画面のメッセージの全文（スクリーンショット）を控え、**自分で Drive のファイルやプロジェクトを消さずに**開発者に共有する（Setup を開き直すと続きから再開します。下の「5. トラブルシューティング」）

**手順 F: 初期設定（「3」）と iPad の登録（「4」）に進む**
1. 管理者用 URL を PC の Chrome で開く（Google 所有者のアカウント）
2. 「3. 初期設定」の順に、管理者パスワード → 店舗設定 → スタッフ・給与条件 → 端末の登録コードを設定する
3. 「4. 店舗 iPad の登録」で iPad を登録する
4. 「今すぐバックアップ」でバックアップが作れることを確認する（管理画面「バックアップ」）
5. 保守作業・障害時の関数（shiftlyMaintenanceBegin など）は、https://script.google.com/home の「Shiftly-Staff (…)」のエディタで、関数を選んで「実行」する。結果は「実行ログ」に表示される（docs/operations-guide.md「9」・docs/incident-response.md）

以下の「1」〜「5」は、手順 D・E・F の詳細と、開発者向けの別の方法です。

## 1. Setup の配置（どちらか一方）

### A. 自己ホスト（推奨）— 管理者アカウントに Setup を置く

**clasp を使う場合（開発者が代行）**
```bash
npm ci
```
```bash
npm run build && npm run build:gas
```
```bash
cd dist/gas/setup && npx @google/clasp create --type webapp --title "Shiftly Setup" && npx @google/clasp push
```
（clasp は管理者アカウントでログインした端末で実行。clasp のログイン情報 `.clasprc.json` はリポジトリにコミットしない）

**ブラウザのみの場合**
1. https://script.google.com/ で「新しいプロジェクト」を作成し、名前を「Shiftly Setup」にする
2. 「プロジェクトの設定」→「appsscript.json をエディタで表示」をオン
3. `dist/gas/setup/` の各ファイルを同名で作成して内容を貼り付け: `appsscript.json`, `Code.gs`（= Code.js）, `Release.gs`（= Release.js）, HTML ファイル `setup`（= setup.html）
4. Cloud プロジェクトの紐づけ（google-api-setup.md §2-5）
5. 「デプロイ」→「新しいデプロイ」→ 種類: ウェブアプリ、実行: 自分、アクセス: 自分のみ → デプロイ

### B. ホスト型 — 配布者のアカウントで公開

`dist/gas/setup/appsscript.hosted.json.txt` を appsscript.json として使い（実行: アクセスしているユーザー、アクセス: Google アカウントを持つ全員）、配布者がデプロイして URL を管理者に渡します。Setup のコードは管理者の権限で動くため、**配布者を信頼できる場合のみ**利用してください。

## 2. セットアップの実行

1. Setup の URL を管理者の Google アカウントで開き、権限を確認して承認
2. 店舗名を入力し「セットアップを開始」
3. 自動工程: アカウント確認 → API 確認 → Shiftly-Staff 作成・コード配置・デプロイ
4. **管理者の操作①**: 「スクリプトエディタを開く」→ 関数 `shiftlyAuthorize` を選んで「実行」→ 権限を確認して許可（Shiftly が作成したファイルのみ操作する権限）→ Setup に戻り「確認して続行」
   - このとき Google ドライブに `Shiftly/`（00_System〜05_Backup）とデータベースが作成され、日次トリガーが登録されます
5. 自動工程: Shiftly-Admin 作成・配置・デプロイ
6. **管理者の操作②**: Admin のエディタで `shiftlyAuthorize` を実行 → 許可 → 「確認して続行」
7. 自動工程: Setup との接続設定 → 接続・DB 整合性・作成物（デプロイ・Google ドライブの構成物・Setup の記録ファイル）の確認
8. **管理者の操作③（完了の条件。D-027）**: https://script.google.com/home のプロジェクト一覧で「Shiftly-Staff (環境ID)」「Shiftly-Admin (環境ID)」が 1 つずつであることを確認し、Setup の確認のチェックを付けて「確認したので再実行」→ 完了（Setup の権限ではプロジェクトを一覧できないため、所有者の確認がないと完了しません）
9. 完了画面に表示される **管理者用 URL**（Google 所有者の PC 用。ブックマーク）と **店舗 iPad 用 URL（Shiftly-Staff）の QR コード**を控える

途中で画面を閉じても、次回 Setup を開くと続きから再開します（完了の状態が確実な工程だけを飛ばします。作成の結果が分からない場合は止めて確認を求めます）。進捗は Google 側（UserProperties と Drive の記録ファイル）に保存され、端末には保存しません。

**v1.3 では、構築済みの環境のアプリの更新・ロールバックを Setup から行いません**（D-027）。構築に使った版と異なる版の Setup では、既存の環境を変更しません。データの復元・更新は Google 所有者の保守作業です（docs/operations-guide.md「9. 保守作業」・docs/update-rollback.md）。

## 3. 初期設定（管理画面）

1. 「システム・保守」: **管理者パスワードを設定**（12 文字以上。店舗 iPad の「管理者ページ」に入るためのパスワード。Google 所有者の画面でのみ設定・再設定できます）
2. 「店舗設定」: 営業時間、営業日の切替時刻、労働時間制度、週の起算曜日、法定休日、締め日・支払日、最低賃金（公式資料で確認した額と根拠）、有給の賃金算定方法、**勤怠・給与の時間基準（標準: シフト基準・予定休憩）** 等 → 「給与規定の確認」
3. 「スタッフ・権限」: スタッフ登録、PIN 設定（任意）、必要なら個別権限と管理用パスコード、各スタッフの「時給ルール」「月給設定」で時給・月給・交通費・手当・雇用条件
4. 「店舗端末」: 登録コードを発行

2〜4 は、iPad を登録した後に店舗 iPad の「管理者ページ」（管理者モード）からも行えます。

## 4. 店舗 iPad の登録

1. iPad の Safari で店舗 iPad 用 URL（Shiftly-Staff。QR）を開く
2. 共有メニューから「ホーム画面に追加」
3. 管理者が発行した登録コードを入力
4. **Google アカウントで iPad にログインしないでください**（店舗 iPad 用 URL はログイン不要。管理者は右上の「管理者ページ」から管理者パスワードで操作します）

## 5. トラブルシューティング

| 表示 | 原因・対処 |
|---|---|
| Apps Script API が無効です | script.google.com/home/usersettings で API をオン。Setup の Cloud プロジェクトでも API を有効化 |
| 別の Google アカウントで作成されています | 管理者のアカウントでログインし直す（取り違え防止） |
| 配布ファイルの検証に失敗 | Setup を正規の配布物で更新 |
| Shiftly-Staff に接続できません | `shiftlyAuthorize` を実行したか確認 |
| `shiftlyAuthorize` が「前回の…の作成の結果を確認できません」で止まる | 前回の実行でフォルダ・DB・環境情報ファイルの作成の結果が分からなかった（D-026 S1）。数分おいて `shiftlyAuthorize` を再実行（作成済みなら検索に反映されて使われる）。Google ドライブに該当のフォルダ・ファイルがないこと（またはゴミ箱に移動したこと）を確認した場合は、エディタで `shiftlyConfirmStorageNotCreated` を実行してから `shiftlyAuthorize` を再実行（確認の操作は検索し直し、見つかったものはそのまま使い、見つからないものだけを作り直す） |
| `shiftlyAuthorize` が「…が 2 つあります」で止まる | 同じ構成物が二重に作られた可能性。Google ドライブの Shiftly フォルダで、使わないほうをゴミ箱に移動してから再実行（自動では選ばない・削除しない） |
| Setup が「記録している…を確認できませんでした」と表示する | 記録しているプロジェクト・デプロイを照会で確かめられなかった（一時的な失敗の可能性）。数分おいて再実行。Apps Script の画面で見つかった場合は「既存の ID を関連付ける」に ID を入力。削除したことを確認した場合だけ、チェックを付けて再実行（作り直す） |
| 開始時に「Setup の記録が見つかりません」と表示される | Setup の記録（UserProperties・Google ドライブの「Shiftly Setup Registry.json」）が見つからない。以前にこのアカウントで構築した場合は、記録ファイルがゴミ箱にないか確認して元に戻し、再読み込みする。初めての構築の場合だけ、確認のチェックを付けて実行（D-026） |
| 確認の工程で「自動では確かめられない項目があります。所有者の確認が終わるまで、構築を完了しません」 | Apps Script のプロジェクト一覧で「Shiftly-Staff (環境ID)」「Shiftly-Admin (環境ID)」が 1 つずつであることを確認し、チェックを付けて再実行（D-027。Setup の権限ではプロジェクトを一覧できないため）。2 つ以上ある場合は、Setup の記録にない ID のほうを使わず、削除せずに開発者に相談する（自動では削除しない） |
| 確認の工程で「この環境の Setup の記録ファイル（Shiftly Setup Registry.json）が 2 つあります」「別の環境の Setup の記録ファイルがあります」 | Google ドライブで「Shiftly Setup Registry.json」を検索し、内容（envId）を確認する。保存している ID（案内に表示）以外のこの環境のファイル・使わない環境のファイルを整理してから再実行（自動では削除しない。D-027・Codex 監査24 A4） |
| 「保存している Setup の記録ファイル（ID: …）が見つかりません」「…ゴミ箱にあります」「…一致しません」 | 保存している ID の記録ファイルを照会で確かめられない、または別の環境のもの。Google ドライブのゴミ箱から元に戻して再読み込みする。新しい環境とは推測せず、上書きもしない（D-027・Codex 監査24 A3）。解決しない場合は開発者に連絡 |
| 「この環境は Shiftly x.y.z で構築されています。この Setup では変更しません」 | 構築に使った版と異なる版の Setup を開いた。v1.3 では Setup による更新を行わない。構築に使った版の Setup を使う |
| 「更新用の接続設定に失敗しました」でリセットを案内された | Shiftly-Staff のエディタで `shiftlyResetSetupPairing` を実行してから、Setup で再実行 |
| Setup が「作成結果を確認できませんでした」「デプロイを確認できませんでした」と表示し、確認のチェックを求める | 画面の案内どおり、Apps Script のプロジェクト一覧・「デプロイを管理」で確認する。ない（または整理した）ことを確認した場合だけ、チェックを付けて再実行（二重作成の防止。D-025 S1） |
| 作成途中で通信が切れた | Setup を開き直して「続きから実行」。同名（環境 ID 付き）のプロジェクトが二重にある場合、レジストリに記録されていない方は手動で削除可 |
| iPad が「登録されていません」 | Safari のデータ消去等で端末トークンが消えた可能性。管理画面で新しい登録コードを発行して再登録（業務データは消えていません） |
